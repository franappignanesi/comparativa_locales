# BARATEAM SEO audit, 2026-10-01

## Confirmed production problems before this change

- `/robots.txt` and `/sitemap.xml` returned 404.
- The library and weekend library shipped loading skeletons rather than their headings and game cards in the initial HTML. `useSearchParams` suspended their entire content despite server-preloaded data.
- The comparison dashboard fetched all visible statistics after hydration.
- Most routes lacked canonical URLs and Open Graph / Twitter sharing metadata. The weekend canonical was relative.
- Account and administration screens were indexable with generic titles.
- Games had no independent, indexable URLs or crawlable catalog pagination.

## Implemented

- Canonicals on the actual production host, `https://www.shuxteam.com`, per-page Spanish titles/descriptions, Open Graph/Twitter cards and a generated PNG sharing image.
- WebSite/Organization data and safe JSON-LD serialization. No fabricated reviews, ratings, prices, availability or rich-result promises.
- Google indexing controls: public pages indexable; account/admin pages noindex; API responses X-Robots-Tag noindex; robots excludes API/admin crawling.
- Sitemap with published dataset modification dates, public routes, catalog pagination and game fiches with price/free-game/editorial content. Empty fiches are noindex and omitted from the sitemap.
- Only the tiny query-parameter observer suspends; the library itself is rendered in build HTML. Query/filter/modal links continue working after hydration.
- Comparison dashboard statistics are preloaded server-side and revalidated daily.
- `/juegos/[slug]`: individual game metadata, PC prices in the native store currency without taxes, source links, relevant games, Shux recommendations where present, VideoGame and breadcrumb data.
- `/juegos` and paginated indexes link to the full catalog through normal HTML anchors. Automatic prefetch is disabled for the large game index to avoid thousands of background requests.
- Game fiches use on-demand ISR rather than rendering all 4,000+ games on every build. The existing daily workflow refreshes their source datasets via deployment; no scraping is started by a fiche request while the public datasets are present.
- Font preconnections and removal of redundant initial anonymous library/dashboard requests.

## Verification

`node scripts/check-seo.mjs` inspects the built HTML. Pass a base URL to additionally check game HTML/prices, schema, sitemap, robots, noindex, 404 responses and the PNG sharing image. Unit tests cover canonical generation, script-safe serialization, stale offer exclusion and native currency handling. Browser checks cover mobile/desktop fiches and query-based library filters.

## Follow-up requiring owner access or real traffic

- Verify a Domain property for `shuxteam.com` in Google Search Console and submit `https://www.shuxteam.com/sitemap.xml`.
- Inspect the library and several game URLs, and monitor actual indexing, impressions, query CTR and canonical selection.
- Measure mobile Core Web Vitals with field data (LCP, INP, CLS); screenshots or a successful build are not performance scores.
- Improve genuine editorial content using Shux's existing game recommendations and relevant video links, rather than bulk keyword stuffing.
- Consider dedicated regional/offer landing pages only when they contain distinct server-rendered content. Do not publish every filter/query combination as an indexable page.
- Search positions and rich results are not guaranteed by technical metadata. Reassess results after crawling and collecting traffic.
